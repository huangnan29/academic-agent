# 自然学术写作与章节优化仓库调研

## 1. 调研目标与边界

本调研服务于“学术 Agent”的章节生成优化，关注如何提高学术文本的清晰度、证据约束、章节适配度、语体自然度和可编辑性。

“降低模板感”不等于对抗检测器。本项目不会：

- 承诺通过知网、维普、Turnitin 或其他 AIGC 检测。
- 使用零宽字符、同形字符、故意语病、随机替词或统计指纹攻击。
- 为了某个检测分数改动真实数字、引用、研究结果或专业术语。
- 把开源仓库的提示词、代码或词表直接复制进应用而不核验许可证。

## 2. 调研对象

| 项目 | 可借鉴方法 | 许可证与采用决定 |
| --- | --- | --- |
| [Academic Humanizer](https://github.com/AIScientists-Dev/academic-humanizer) | 先诊断再改写；主张强度与证据强度匹配；数字、公式和引用不得变化；区分论文与研究计划语体 | Skill 文件声明 MIT，但 GitHub 仓库元数据未识别标准许可证。本轮只借鉴方法，不复制文件 |
| [humanize-writing](https://github.com/Shirhussain/humanize) | 先识别语域；保留事实与引用；检查空泛开头、连接词堆叠、同构句式、重复总结和段落节奏 | MIT；可把通用检查思想重写为本项目自己的中文规则 |
| [PaperSpine](https://github.com/WUBING2023/PaperSpine) | 用 motivation、贡献、证据和结果验证构成论文主线；为每个写作单元记录功能、证据和验收条件 | MIT；适合作为“章节计划 + 证据矩阵”的架构参考，不引入其整套工作流 |
| [XtraGPT](https://github.com/NuoJohnChen/XtraGPT) | 按 Title、Abstract、Introduction、Background、Evaluation、Conclusion 等章节使用不同修订标准；全文上下文保持跨节一致 | 仓库许可需在实际引入模型前单独复核；本轮只采用论文公开的方法结论，不集成模型 |
| [blader/humanizer](https://github.com/blader/humanizer) | 保留信息而不是照搬原句结构；作者样本文风优先；不为增加“人味”而发明事实 | MIT；只吸收事实保真与语体校准原则 |
| [Autonovel Anti-Slop](https://github.com/NousResearch/autonovel/blob/master/ANTI-SLOP.md) | 检查段落模板重复、句长过度统一、空泛过渡词和三段式对称 | 仓库元数据未识别标准许可证，且面向小说；只作为反例清单，不复制词表 |

相关研究提供了两项更可靠的产品方向：

1. [XtraGPT（ACL 2026）](https://aclanthology.org/2026.acl-long.47/)把学术修改视为“标准引导、上下文感知、人与模型协同”的迭代过程，而不是一次表层润色。
2. [AI-Slop to AI-Polish](https://arxiv.org/abs/2504.07532)显示，生成多个候选并以写作质量标准选择，比只依赖一个通用提示更有希望提高质量；这适合后续阶段，不适合首批直接增加成本。
3. [Measuring AI Slop in Text](https://arxiv.org/abs/2509.19163)强调质量判断与连贯性、相关性等可解释维度相关，不能把单一“像不像 AI”分数当作写作质量。

## 3. 明确排除的方案

以下类型仓库不进入实现候选：

- 以“绕过 GPTZero / Turnitin / 知网”为首要目标的检测器攻击项目。
- 通过多模型串洗、随机改错、同义词大批替换、标点扰动或隐藏字符改变检测分布的项目。
- 没有明确许可证、来源数据或事实保真机制，却宣称“100% Human”的项目。
- 自动补写样本、统计显著性、实验结果、访谈或问卷数据的提示词。

## 4. 可落地的独立方法

### 4.1 章节角色先于文风

生成前先识别章节承担的功能，而不是只读取标题：

- 摘要：问题、方法、主要内容/结果、结论与边界。
- 绪论/问题提出：研究情境、缺口、问题、目标、论文推进路径。
- 文献综述/理论：概念边界、研究脉络、分歧、缺口与本研究位置。
- 方法/设计：对象、材料、步骤、变量/模块、可复现条件与限制。
- 结果/实现：只陈述已有证据、真实数据或真实系统产物；没有数据时不得模拟结果。
- 讨论：解释结果、对照文献、适用边界、替代解释与局限。
- 结论：回答研究问题，区分已完成工作、局限和有条件的展望。

### 4.2 主张—证据约束

每个关键主张标记为以下一种：

- 已有文献支持。
- 已有项目数据、图表、代码或测试支持。
- 基于前文的分析推论。
- 尚缺证据，只能降级表述或提示用户补充。

引用只能使用项目文献 ID；数字、样本、显著性、图号、表号和结果不得由润色步骤创造。

### 4.3 自然学术表达

“自然学术”是质量策略，不是检测器策略：

- 删除不承载信息的套话和重复总结。
- 避免连续段落使用相同开头、相同四段式模板或等长排比。
- 让句长变化服务论证：定义和结论宜短，限定条件和机制解释可适当展开。
- 用具体对象、变量、方法、文献关系替代“具有重要意义”“相关研究表明”等空泛句。
- 保留必要的专业术语、被动语态和不确定性表达，不为“人味”牺牲准确性。

### 4.4 内容多元化的安全边界

表格、图、公式和代码不是装饰项：

- 表格适合真实对比、变量定义、功能/案例/文献矩阵。
- 图适合流程、概念关系、系统架构或真实数据趋势。
- 公式只在学科、变量定义和推导上下文完整时生成。
- 代码只在系统实现、算法或数据处理章节中出现，并标明其来源与可运行边界。
- 缺少真实数据时只能输出“建议的图表规格”，不能画出虚假结果图。

## 5. 本轮采用结论

第一批不引入外部“人类化”模型，也不复制第三方 Skill。建议先实现本项目自己的章节角色路由、四种透明优化策略、主张—证据约束和可解释质量报告；用户样本文风、多候选排序和图表产物放到后续阶段。
